Goal

Let recent performance count for more than old performance smoothly --
an event's influence fades gradually with age instead of dropping to zero
the instant it crosses a fixed window boundary -- as an opt-in
alternative to PR 9's flat lookback_hours window. Everyone not using the
new option must observe byte-identical behavior to PR 9.

Design decisions already made for you

These were settled in the 2026-07-23 design interview and folded into the
plan's PR 10 section. Implement them exactly:

1. No signature change to aggregate_stats. PR 7 already shipped its
   weight_fn: Callable[[MetricsEvent], float] | None = None parameter,
   unused until now. This PR is the first real caller of it -- do not
   touch stats.py itself; this PR's only production-code change is to
   src/nygen_router/policies/score_based.py.

2. ScoreBasedPolicy gains one new constructor parameter:

       half_life_hours: float | None = None

   Validate: when not None, must be > 0 (same validation style as
   lookback_hours already has from PR 9).

3. When half_life_hours is None (the default): behavior must be
   byte-identical to the PR 9 policy -- same query bound (derived from
   lookback_hours as before), same flat/uniform weighting (weight_fn left
   as None when calling aggregate_stats). This is a hard requirement,
   not a loose approximation -- write a regression test that runs the
   same scenario through an equivalent PR-9-shaped policy and a
   half_life_hours=None policy and asserts identical results, not just
   "looks similar".

4. When half_life_hours is set (not None): it takes over entirely from
   lookback_hours for this policy instance -- the two are not combined,
   and lookback_hours is not read or used in this mode at all. Do not
   attempt to make them interact or validate them against each other.
   Specifically:
   a. Query bound: since = self._now() - timedelta(hours=6 *
      half_life_hours). The multiplier 6 is a fixed internal constant --
      six half-lives, chosen because weight at that age is 0.5**6 ~=
      1.6%, small enough to be immaterial. It must not be exposed as a
      constructor parameter or otherwise made user-configurable.
   b. Weight function: build weight(event) = 0.5 ** (age_hours /
      half_life_hours), where age_hours = (self._now() -
      event.timestamp) in hours (as a float, e.g.
      (self._now() - event.timestamp).total_seconds() / 3600.0). Pass
      this as aggregate_stats's weight_fn argument in place of leaving
      it None.
   c. Everything downstream of aggregate_stats (calculate_provider_score
      in PR 8's scoring.py) needs no change: ProviderStats' count fields
      are already typed float (from PR 7, specifically reserved for
      this), so a fractional decayed effective count flows through PR
      8's existing blend formula unmodified. Do not touch scoring.py in
      this PR.

5. Diagnostic counts stay exact and unweighted. recent_error_count,
   rate_limit_count, and timeout_count on ProviderStats are computed the
   same way regardless of half_life_hours -- plain, exact tallies of
   what happened within the queried window. Decay must never be applied
   to these three fields even when half_life_hours is set (they already
   are not read by any weighted computation, since aggregate_stats's
   existing implementation -- unchanged by this PR -- computes them as
   plain counts; this decision exists to make explicit that this PR must
   not change that).
